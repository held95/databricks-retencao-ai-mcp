## 1. AI Functions — `gold_tickets_ia`

`ai_query('databricks-meta-llama-3-3-70b-instruct', prompt, responseFormat => 'STRUCT<classificacao:STRUCT<sentimento,motivo,urgencia>>', failOnError => false)`
roda **dentro do SQL warehouse**, em lote, sobre os **200 tickets mais recentes** de `silver_tickets`
(limite para custo/tempo; ~1 min). A saída estruturada garante JSON válido; `failOnError => false` devolve
`errorMessage` por linha em vez de derrubar a consulta (coluna `erro_llm`).

Colunas: `ticket_id, cliente_id, data_abertura, canal, categoria_original, texto, sentimento, motivo, urgencia, erro_llm, classificado_em`.

## 2. Funções do Unity Catalog como tools de agente

SQL table functions com `COMMENT` na função e em cada parâmetro — o managed MCP server
`/api/2.0/mcp/functions/workspace/telecom_ai` expõe esses comentários como **descrição da tool** para o LLM.
Governança: o agente só recebe `EXECUTE` na função, sem acesso livre às tabelas; nenhuma retorna PII.

| Função | Retorno |
|---|---|
| `workspace.telecom_ai.get_cliente_360(p_cliente_id STRING)` | visão 360 de um cliente (features, último ticket, score/faixa de risco) |
| `workspace.telecom_ai.clientes_alto_risco(p_uf STRING, p_limite INT)` | clientes **ativos** por `score_risco` desc; `p_uf` NULL/'' = todas; limite 1–100 |
| `workspace.telecom_ai.resumo_risco_uf()` | por UF: clientes, churn, taxa, alto risco, score médio, receita e receita em risco |

Detalhe técnico: `LIMIT` não aceita parâmetro dentro de SQL UDF (`INVALID_LIMIT_LIKE_EXPRESSION.IS_UNFOLDABLE`),
então `clientes_alto_risco` usa `row_number()` + filtro `rn <= p_limite`.

## 3. Vector Search — `politicas_index`

- Endpoint: `vs-telecom` (STANDARD, id `6ea3bbe8-45f3-406f-a9a2-201b66d45f4a`)
- Índice: **`workspace.telecom_ai.politicas_index`** — Delta Sync, embeddings gerenciados (`databricks-gte-large-en`
  sobre `texto`), pk `politica_id`, pipeline **TRIGGERED** (sync pipeline `e0b4c604-c91a-412b-ab52-376f9a73e390`),
  subtipo HYBRID (vetor + palavra-chave), **15 políticas indexadas**.
- Fonte: **direto na streaming table do pipeline `silver_politicas`** (tem `delta.enableChangeDataFeed = true`).
  Funcionou sem precisar da cópia `politicas_kb` — o fallback existe no script, mas não foi usado.
- Tempo até `ready`: **~17 min** no Free Edition (≈15 min em "pending endpoint provisioning", mesmo com o endpoint ONLINE;
  depois ~2 min de setup do pipeline e sync).

**Teste de similaridade** — *"cliente insatisfeito com sinal querendo cancelar"* (top 3):

| modo | 1º | 2º | 3º |
|---|---|---|---|
| ANN (só semântico) | P015 Fluxo padrão de cancelamento (0.719) | P006 Downgrade assistido (0.690) | P010 Boas-vindas clientes novos (0.667) |
| **HYBRID** (semântico + keyword) | **P003 Visita técnica prioritária por problema de sinal (0.969)** | P010 (0.961) | P006 (0.954) |

> Lição: `gte-large-en` é um modelo de embedding **em inglês**; em pt-BR a busca puramente semântica pegou a
> intenção "cancelar", mas perdeu "sinal". O modo **HYBRID** (`query_type="HYBRID"`) traz a política certa (P003)
> em 1º — é o modo recomendado para o agente de RAG. Alternativa seria um embedding multilíngue
> (os dois disponíveis no Free Edition, gte e bge, são em inglês).

## 4. Genie space "Retenção Telecom"

- **space_id: `01f1d2578a841c018d73b75bc354b90e`**
- URL: https://dbc-1d83b389-044f.cloud.databricks.com/genie/rooms/01f1d2578a841c018d73b75bc354b90e
- Criado 100% via API: `w.genie.create_space(warehouse_id, serialized_space=<JSON v2>, title, parent_path)`
  (pasta `/Workspace/Users/<seu_usuario>/retencao_ai_mcp`), warehouse `568abc53566f5fa8`.
- Tabelas: `gold_cliente_360`, `gold_kpis_uf_plano`, `gold_tickets_ia`.
- Instruções em pt-BR (definição de churn, faixas de risco, "receita em risco", foto de 30/09/2026, sem PII,
  "gold_kpis_uf_plano é 1 linha por uf×plano → sempre agregue"), 3 exemplos de SQL e 5 perguntas sugeridas:
  - Qual a taxa de churn por UF?
  - Quais os 10 clientes ativos com maior score de risco em SP?
  - Qual a receita mensal em risco por plano?
  - Qual a distribuição de sentimento dos tickets classificados pela IA por motivo?
  - Quantos tickets de urgência alta existem por canal?

**Teste via Conversation API** (`w.genie.start_conversation_and_wait`) — *"Quais as 5 UFs com maior receita em risco?"*

```sql
SELECT uf, SUM(receita_em_risco) AS receita_em_risco
FROM `workspace`.`telecom_ai`.`gold_kpis_uf_plano`
WHERE receita_em_risco IS NOT NULL
GROUP BY uf ORDER BY receita_em_risco DESC LIMIT 5
```
Resposta: MG R$ 879,40 · PR R$ 749,50 · SP R$ 749,40 · RJ R$ 639,60 · CE R$ 539,70 — **bate exatamente com `resumo_risco_uf()`**.

> Lição (boa história de entrevista): na 1ª versão, sem a instrução de agregação, o Genie pegou o ranking
> **linha a linha** (uf×plano) e respondeu SP R$ 479,70 no topo — errado. Adicionei 1 instrução + 1 SQL de exemplo
> (`update_space`) e a resposta passou a ser correta. Instruções/exemplos são o "fine-tuning" do Genie.
